# U_luv — Mandatory instructions for AI coding agents and regular AI Chats (FINAL v2.0)

**STOP/READ:** Before tools, scripts, `.env` inspection or any integration work, read `docs/security/00_NON_NEGOTIABLE_GUARDS.md` and `docs/START_HERE.md`. These rules override older/archive files. The user has not granted AWS spending/upload authorization by sharing a ZIP, AWS account name, existing buckets, tokens, or approval to *write code*. Never infer approval.

## Strict secret/privacy rules
- **NEVER inspect, print, ingest into model context, search, modify, copy, commit, archive or output real** `.env`/`.env.*` (except `.env.example`), AWS credentials/config files, secret-manager values, CloudFront signing private keys, service account JSON, store/API/payment tokens, keystores or real customer media/data. Do not ask users to paste secrets into chat. Use `.env.example` placeholders. Operators manage actual secrets themselves.
- If a secret value unexpectedly appears in a tool output, do not reproduce it. Stop affected workflow; ask owner to rotate/revoke if appropriate. Do not store secrets in progress docs, QA logs, code, stack traces, screenshots or ZIPs. Presigned S3 PUT URLs and signed CloudFront GET URLs are sensitive bearer tokens: redact all query parameters and do not persist them in docs or telemetry.
- `npm run test:secrets` and `npm run test:cloud-guards` MUST pass before packaging. Package using the safe packaging script; fail closed if scanner reports risky files.

## Cloud / payments rules: DENY by default
- P00–P16 **Java DynamoDB Local** only; no Docker. **Never access AWS DynamoDB production/staging tables before the explicitly owner-approved P17 gate.** Local scripts accept only loopback DynamoDB endpoints.
- Owner will **manually** set up TWO DEV private S3 buckets (persistent profile media; temporary chat/Local/Activity media) and ONE DEV CloudFront distribution with two private S3 origins and trusted key-group signed URL validation, in the initial phases. Provisioning is owner-only and is **not proof that an agent may use AWS**.
- AI/scripts start in `MEDIA_STORAGE_DRIVER=local`. Generate adapters, test doubles, fixtures and dry-run documentation. **Do not make any AWS request (including HEAD/List), upload even one test image, issue/consume a real presigned URL, invalidate CloudFront, create/modify/delete resources, configure IAM, use SES, or spend funds**, without new, explicitly scoped human authorization for that precise action. If approval is missing, ask owner to do it manually and mark cloud verification UNVERIFIED.
- An approval must specify account/environment, operation, exact bucket/prefix/resource, file count/size, cost guard, deadline, cleanup, and manual or agent actor. Approval for one operation is NOT approval for another. No `--force`, `--yes`, env-var or prior conversational approval grants general permission. Prefer owner doing real AWS operations manually. See `docs/security/02_CLOUD_ACTION_APPROVAL.md`.
- Do not automatically use available ambient AWS credentials or load AWS profiles. Never reveal tokens. Give AI agents no cloud credentials; owner must maintain separate least-privilege runtime/operator identity. No AWS deployment, real charging, refunds or store publishing without separate explicit owner gate. Google Play sandbox P16, production/cloud/P17; Apple StoreKit at later iOS stage.

## Architecture and development
- Preserve **18 feature-aligned DynamoDB tables**, H3 Resolution 6, selectable 0–10 / 10–35 / 35–50 km distance bands and full 0–50 discovery, nearest-band-first ordering, zero popularity/pay-to-boost ranking.
- Media: 2 DEV private S3 buckets + one DEV CloudFront distribution (owner-created early); separately approved production resources P17. S3 presigned PUT for upload, CloudFront signed GET for delivery; backend may include short-lived signed URLs in *authorized* profile/feed/chat API responses. No signed URLs in canonical records. Local media adapter remains usable through all phases and is default for automated QA.
- Use feature-oriented Fastify/TypeScript `apps/api/src/features/<name>/` and Flutter `apps/flutter_app/lib/features/<name>/` with `shared/` for true reuse, not an overengineered microservice architecture. `apps/admin` remains distinct.
- Read only `docs/START_HERE.md`, current Pxx, `docs/implementation/PROGRESS.md`, `docs/NEXT_STEP.md`, relevant security and 1–2 necessary architecture docs. Don't repeatedly read entire handoff.
- For EACH small vertical slice: D1 backend+real **local** DB; D2 Flutter integrated UI; D3 end-to-end/recovery; T1 unit/static; T2 DynamoDB Local/API; T3 Flutter/regression and manual checks. AI Chat must generate complete runnable source/tests, run tools available, label unavailable tests UNVERIFIED with exact Windows commands. Fix failures and rerun.
- Never report a test as PASSED without real execution. Each update ZIP includes only changed project-relative source/scripts/tests plus current `docs/` folder; omit secrets and binaries. Update PROGRESS/EVIDENCE/NEXT_STEP once at slice completion. First work item is real P00 API↔Java DynamoDB Local↔Flutter roundtrip.
- **MANDATORY MANUAL-TEST ESCALATION:** When automation fails repeatedly, remains unreliable after a justified repair, or cannot exercise real-device/GUI/owner-only behavior, **proactively ask the owner to perform a specific manual test** with exact commands, steps, expected outcomes and sanitized feedback. Do this before further speculative patches. Keep automated FAIL and manually observed PASS as separate evidence; never suppress the test. A narrowly owner-accepted local-development exception does not pass the automated gate or authorize phase/release completion. See `docs/qa/MANUAL_VERIFICATION_ESCALATION.md`.
