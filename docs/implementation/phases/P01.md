## Phase scope and explicit exclusions

Implement only the work required to make this phase a usable feature slice. Respect the core product contract and 18-table schema. ## Development sections

### D1 — Backend, database and contracts

Implement accounts, provider links, verified email mapping, expiry/rate limiting on OTP issuance, idempotent account creation, server-verified Google identity claims, DOB policy, deletion/deactivation state, and admin-restrictable eligibility. No raw OTP or identity secret in logs.

**Required outputs:** API handlers + validation, repository/model adapters, precise PK/SK usage, migration/seed changes, unit test fixtures, documented error codes; no unbounded scans.

### D2 — Flutter/UI and actual integration

Build Flutter sign-in, email verification, DOB/eligibility notice, consent, rejection and retry screens; preserve usable error states and accessible controls.

**Required outputs:** screen/state management, typed API client, loading/error/empty states, accessible UI actions, Flutter unit/widget tests. Do not leave demo-only buttons.

### D3 — End-to-end behavior, negative cases and recovery

Integrate provider callback/session refresh/logout/re-entry and duplicate email/provider-link collisions; distinguish mocked local identity fixture from real provider production setup; include local email OTP outbox and Google test-provider setup; do not require real SES for P01 development.

**Required outputs:** fully connected backend/Flutter flow, idempotency/retry/security checks, scope-specific manual test instructions, and failure-state UI. Do not prematurely close a phase with disconnected FE and BE.

## Testing sections (code + actual evidence)

### T1 — Unit, static and deterministic tests

Test age boundary, malformed/expired/replayed OTP, identity subject hashing, secret redaction, provider mapping and unit auth middleware; run static checks.

**Commands intended after P00:** `npm run typecheck`, `npm run lint`, `npm run test:unit`, `flutter analyze`, `flutter test`. Commands must be implemented in the actual project scripts before claiming executable.

### T2 — Real DynamoDB Local + API integration

DynamoDB Local transaction race: two concurrent first logins for same provider result in one unique uid; revocation and forbidden account state enforced at API.

**Commands intended after P00:** `npm run test:integration`, `./scripts/verify/verify-phase.ps1 -Phase P01` (Windows PowerShell wrapper). Where AWS/S3/store is needed, local stand-ins are separately labeled; do not misrepresent them as live provider checks.

### T3 — Flutter, workflow, accessibility and human fallback

Flutter registration, duplicate signup, OTP retry, session restore, invalid age, denied account, logout and offline scenarios; real Google provider checks manual if unavailable; use local email OTP outbox adapter, with actual AWS SES integration deferred to P17.

**Commands intended after P00:** `flutter test integration_test` (where SDK/device supports); Playwright admin/browser tests for relevant phases; operator smoke steps in `docs/manual/LOCAL_START_AND_VERIFY.md`.
