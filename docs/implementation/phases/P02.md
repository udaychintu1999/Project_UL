## P02 boundary — exact feature behavior

- One public `@handle` per account, immutable private P01 UID; Dating and Friendship maintain separate names/text/photos and independent activation requests.
- Conditional wizard: Common → enabled mode details/photos → Review. Keep **horizontal swiping**, Back, server-gated forward actions and a **single Save & Next**. A mode needs two distinct owner-READY assigned images before Continue; max six per mode; photo files may be reused across modes.
- Owner-only private local media, proper image sanitation, no raw DOB/email/internal IDs in preview. Self-declared DOB determines computed age, not verified identity. Coarse city is not trusted location.
- P02 activation produces `inactive`, `paused_ineligible` or `pending_trusted_locality`, but **never** a discovery pointer or publicly discoverable profile. P03 must implement H3 R6, trusted locality, viewer authorization and atomic pointer lifecycle separately.
- Preserve P01 session and device-bound authentication, the 18-table structure, Java DynamoDB Local and default local media. Real AWS/payments/cloud production integration is separately approved later.
