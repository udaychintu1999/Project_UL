# P04 — Shared Connect wallet, free grants and ledger

**Status:** NOT STARTED · **Feature group:** Wallet · **Prerequisites:** P01  
**Primary tables:** uluv_wallet; uluv_operations  
**User-facing outcome:** 4 free monthly credits for self-identified women, 2 for other eligible users; free first; no rollover; durable paid ledger; concurrency-safe debits.

**Phase environment rule:** Java 17+ DynamoDB Local (no Docker), local media adapter for automatic tests; owner-created DEV S3/CloudFront is available only for separately authorized limited testing; no real AWS DynamoDB/production media or payment-provider integration in P00–P15. ## Development sections

### D1 — Backend, database and contracts

Implement canonical balance, immutable ledger, idempotency keys, conditional debit, monthly anniversary grants, credit source order and controlled eligibility changes; pricing configuration without enabling real payments yet.

**Required outputs:** API handlers + validation, repository/model adapters, precise PK/SK usage, migration/seed changes, unit test fixtures, documented error codes; no unbounded scans.

### D2 — Flutter/UI and actual integration

Build Flutter wallet/balance/history screens, no-credit state, clear action costs and renewal explanation; show paid credit pack previews as non-purchasable until P16.

**Required outputs:** screen/state management, typed API client, loading/error/empty states, accessible UI actions, Flutter unit/widget tests. Do not leave demo-only buttons.

### D3 — End-to-end behavior, negative cases and recovery

Integrate operation replay/recovery, failed debit compensation where required, simultaneous-device behavior and free-vs-purchased spending; do not issue grants repeatedly at login.

**Required outputs:** fully connected backend/Flutter flow, idempotency/retry/security checks, scope-specific manual test instructions, and failure-state UI. Do not prematurely close a phase with disconnected FE and BE.

## Testing sections (code + actual evidence)

### T1 — Unit, static and deterministic tests

Unit-test grant calendar edge cases (month ends/leap years), 4/2 eligibility, FIFO free grant validity, no rollover, insufficient balance, and account change effective next grant.

**Commands intended after P00:** `npm run typecheck`, `npm run lint`, `npm run test:unit`, `flutter analyze`, `flutter test`. Commands must be implemented in the actual project scripts before claiming executable.

### T2 — Real DynamoDB Local + API integration

Real DynamoDB Local concurrent grants/debits/refunds and replay; invariant: never negative, every successful debit exactly one ledger event, every duplicate exactly zero further charge.

**Commands intended after P00:** `npm run test:integration`, `./scripts/verify/verify-phase.ps1 -Phase P04` (Windows PowerShell wrapper). Where AWS/S3/store is needed, local stand-ins are separately labeled; do not misrepresent them as live provider checks.

### T3 — Flutter, workflow, accessibility and human fallback

Flutter wallet balance updates, offline/retry failure, permission flow and visible credit terms; manually inspect critical balance and transaction history.

**Commands intended after P00:** `flutter test integration_test` (where SDK/device supports); Playwright admin/browser tests for relevant phases; operator smoke steps in `docs/manual/LOCAL_START_AND_VERIFY.md`.
