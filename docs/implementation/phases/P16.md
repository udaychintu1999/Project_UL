## Development sections

### D1 — Backend, database and contracts

Complete authoritative verified purchase processing: Google Play Billing purchase-token validation, authenticated product catalog, receipt replay prevention, unique transaction IDs, idempotent credit grants, reversals and refund/chargeback handling. Local DynamoDB tests still mandatory. **Output:** payment-provider abstraction, verified grants ledger, product/pricing contracts, production infrastructure plan (unapplied), negative cases and runnable tests.

### D2 — Flutter/UI and actual integration

Integrate Android Google Play Billing sandbox into the existing wallet UI, obtain products/prices from the proper storefront, implement purchase/cancel/restore/error states. If Indian alternative gateway is chosen and program-eligible, add its compliant opt-in purchase path. Define StoreKit interface and UX for later iOS release without claiming iOS integration passed.

**Output:** customer-visible real sandbox flow and provider-neutral state management, no fake success/credit minting.

### D3 — End-to-end behavior, negative cases and recovery

Run or prepare purchase → server verification → exactly-once credit grant → refund reconciliation. Handle duplicate callbacks, signed invalid receipts, canceled purchase, network crash and pending store transactions. Review official provider requirements and cloud staging checklist. **No production table creation or AWS release deployment without founder authorization.**
