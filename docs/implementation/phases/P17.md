# P17 — Real AWS production integration, full-system QA and release gate

**Status:** NOT STARTED · **Prerequisites:** P00–P16 · **Feature group:** Real AWS + payments + release

**Scope:** This is the first phase where production/staging AWS DynamoDB tables, AWS S3, CloudFront, ECS (and supporting IAM/SES as required) may be provisioned and integrated following **explicit founder authorization**. All 18 tables must exist in the approved AWS account and Region **before production release**. Google Play payment sandbox and backend receipt verification must succeed before enabling live Connect-credit sales.

## Development sections

### D1 — Backend, database and cloud configuration

Using separately reviewed IaC/runbooks, provision AWS staging and, only when approved, production resources: all **18 DynamoDB tables**, PK/SK and TTL where applicable, encryption, PITR/backup, least-privilege IAM policies, region and capacity/cost alarms; configure two separate private S3 media buckets (persistent profile, temporary chat/local/activity), one CloudFront distribution with two OAC origins and signed URL behaviors, ECS/API and required email service. **No hardcoded production credentials**. Prevent local endpoint and dev token in production. Keep Java local DB suite available for reproducibility.

### D2 — Flutter, media and payment integration

Switch production app configuration to approved API/cloud, real S3/CloudFront secure media retrieval and 7-day removal, real production-store catalog after verified sandbox and store approvals. Keep fallback error UX. Android release is primary; iOS StoreKit release occurs in a subsequent explicit iOS stage with equivalent tests.

### D3 — End-to-end, negative cases and recovery

Run founder-critical real staging workflows: signup → profiles/photos → H3 discovery → Likes/Like Back/paid Connect → chat photo and 7-day expiry; Friendship request → acceptance; Local feed up to 5 photos/comments/reactions/activity expiry; report/moderation; credit purchase validation and refund; rate limits, security, restore/rollback and disaster recovery. No silent publishing or live charging.

Re-run Java DynamoDB Local 18-table suite and API/credit concurrency/H3/no-Scan checks; additionally execute real staging DynamoDB (IAM/conditional writes/capacity), actual S3 upload/read/deletion/retention and CloudFront authorization, backup/recovery checks. Mark any unexecuted provider/device test **UNVERIFIED**, and block release on P0 gaps.

## Mandatory secure media/signing acceptance (v1.2)

Follow `docs/architecture/12_S3_CLOUDFRONT_SIGNED_URLS.md`. **S3 presigned upload URLs, private S3, CloudFront signed GET URLs, trusted key groups, OAC, server-side media ACL, expiry/deletion and cache exposure must not be omitted or replaced by public URLs.**

- Real AWS staging must verify valid/expired/tampered S3 presigned PUT and CloudFront signed GET; reject direct S3 public GET and unsigned CloudFront private media GET.
- Confirm backend enforces profile/post/chat viewing permissions before signing. Validate upload completion, original/variant deletion, expiry, blocked users, global history clear, cache residual access and reporting of any non-instantaneous revocation window.
- Test key-group rotation, secret absence from mobile apps, private access logs, upload caps, orphan staging cleanup, idempotent retries and cost baseline; no production release with private-media P0 checks unverified.
