# OWNER MANUAL RUNBOOK — early DEV S3 and CloudFront

**Do these steps yourself in AWS Console, outside AI tool sessions.** Do not paste account details, credentials, PEM, console screenshots showing secrets or signed URLs into Chat/agent. Creation and later read/write tests can incur charges; configure billing alerts first. The AI must not run AWS CLI/CloudFormation/Terraform apply, upload fixtures or invoke signed URLs on its own. DEV resource creation is not blanket approval to test.

1. **Environment isolation:** Choose dedicated DEV AWS account or explicit isolated DEV resource namespace. Confirm Region in your own console. Prepare a budget alert and log costs. No production AWS DynamoDB tables here—Java DynamoDB Local remains authoritative until P17.
2. **Bucket A (longer-lived profile media):** Create globally unique DEV bucket; label it persistent. Keep S3 Block Public Access **ON**, Object Ownership bucket-owner enforced, ACLs disabled, encryption enabled. Do NOT use website hosting or public ACLs.
3. **Bucket B (temporary media):** Create distinct DEV bucket for chat, Local Feed and Activity images. Same private settings; design `staging/` prefixes and appropriate lifecycle safety net for orphan objects; time-based visibility/deletion remains application-controlled, not solely S3 Lifecycle.
4. **CloudFront distribution:** Create ONE standard DEV distribution with TWO S3 REST origins, one for each bucket, and path behaviors `/persistent/*` and `/temporary/*`. Validate origin path/prefix mapping in design before real testing. Default behavior must not allow unauthorized private media.
5. **OAC:** Attach Origin Access Control to both S3 origins with recommended request signing. Restrict bucket policies to the intended distribution and allowed object-read operations. Do not enable public object access for a 'quick test'.
6. **Signed access:** Create CloudFront public key and trusted key group, require signed URLs on every private media cache behavior including fallbacks. Keep the corresponding private signing key in an owner-controlled secrets manager, unavailable to AI agents and Flutter. Use short-lived GET URLs.
7. **CORS (if needed):** For signed browser uploads, scope to explicit development origins and methods, not wildcard admin APIs. Flutter mobile direct PUT may not require browser CORS. Never allow anonymous public GET via the bucket.
8. **Media prefixes:** DEV persistent object keys for profile media; DEV temporary for chat/post/activity. Use random IDs, separate pending staging objects and verified ready objects. Reuse one persistent asset across enabled user profiles by `mediaId` reference.
9. **Record NON-SECRET config only:** Bucket aliases/names if desired, CloudFront DEV domain and public key ID, region, distribution ID for owner reference (avoid placing account-identifying details in shared ZIP). Keep signing private key, AWS secrets and real presigned URLs completely outside `docs/` and AI tools.
10. **Initial acceptance checks:** Owner visually reviews privacy/OAC/HTTPS/default behavior/signature requirement. If you want a **real upload test**, separately approve or manually run ONE synthetic fixture with small size and cleanup per `docs/security/02_CLOUD_ACTION_APPROVAL.md`. No routine agent auto-test and no unapproved CloudFront request.
11. **Backend adapter:** Implementation begins with local `MEDIA_STORAGE_DRIVER=local`; optional dev AWS adapter is controlled by owner outside automated suites. API returns S3 presigned PUT after authentication and CloudFront signed GET after object/parent authorization. Signed thumbnails may be embedded in authorized list/detail responses; never persist/log URLs.
12. **Production:** P17 separately provisions two PROD buckets and one PROD CloudFront distribution, and real AWS DynamoDB tables, with distinct owner approval. DEV buckets must never serve production content.

Review architecture `docs/architecture/12_S3_CLOUDFRONT_SIGNED_URLS.md`, `13_TWO_BUCKET_MEDIA_ARCHITECTURE.md`, `docs/security/01_ENV_AND_SECRETS_HANDLING.md`. There is intentionally **no executable AWS provisioning/upload script** in the handoff.
